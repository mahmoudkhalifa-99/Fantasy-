# فانتازي الدورات الشعبية

## تشغيل محلي
```bash
npm install
npm run dev        # http://localhost:3000 (البيانات بتتحفظ في data/tournament.json)
```
محليًا لوحة المنظم مفتوحة لو `ADMIN_KEY` مش مضبوط. لو عايز تجرب القفل: `ADMIN_KEY=1234 npm run dev`.

## النشر على Vercel
1. ارفع المشروع على GitHub، وفي Vercel: **Add New → Project** واختار الريبو (هيتعرف عليه كـ Vite تلقائيًا).
2. **مفتاح المنظم:** Project → **Settings → Environment Variables** → أضف `ADMIN_KEY` بقيمة طويلة وسرية.
   من غيره لوحة المنظم بتفضل مقفولة. بتدخلها من زر "المنظم" وتكتب المفتاح.
3. **التخزين:** Vercel مش بيسمح بالكتابة على ملفات، فالبيانات بتتحفظ في **Upstash Redis**:
   Project → **Storage → Marketplace → Upstash Redis** → اربطه بالمشروع.
4. اعمل **Redeploy** بعد إضافة المتغيرات.

من غير Redis التطبيق بيشتغل لكن البيانات هتتصفر كل شوية (ذاكرة مؤقتة)؛ الهيدر `X-Storage` في `/api/tournament/data` بيقولك `redis` أو `memory`.

## الحماية (على السيرفر)
- تعديل الفرق واللاعبين والمباريات والنتائج والإعدادات: بمفتاح المنظم بس.
- كل مشترك بيحفظ تشكيلته هو بس: الجهاز بيبعت توكن سري، وأول حفظ بيسجّل الملكية. محدش يقدر يعدل تشكيلة جهاز تاني.
- السيرفر بيتحقق من التشكيلة (7 لاعبين، الميزانية، الحد من الفريق، الخطة، الكابتن)، والجولات اللي بدأت متتغيرش.
- أرقام الموبايل وجهات الاتصال بتظهر للمنظم بس.
- تشكيلات المشتركين مخزنة منفصلة، فحفظ مشترك ما بيمسحش تشكيلة غيره.

## الملفات
- `src/` الواجهة · `api/tournament/` الـ API على Vercel · `server.ts` سيرفر التطوير المحلي فقط
- `server/logic.ts` الصلاحيات والتحقق · `server/*Storage.ts` التخزين · `server/defaultData.ts` بيانات الدورة الافتراضية

## التسجيل المباشر للمباراة
لوحة المنظم ← تبويب **🔴 مباراة مباشرة**: اختار المباراة وادوس "ابدأ"، بعدين اختار الحدث (هدف/صناعة/كارت/...) وادوس على اللاعب.
النتيجة والهدافين وإحصائيات اللاعبين (نقاط الفانتازي) بتتحدّث لحظيًا، والمشتركين بيشوفوها تلقائيًا كل ~8 ثواني. فيه زر "تراجع" لآخر حدث.

## بيانات اللاعب (زي الفانتازي)
في سوق اللاعبين وشاشة التبديل: اسحب اللاعب لليمين (أو دوس 📊) فتظهر شاشة بيانات اللاعب: الماتش الجاي، إجمالي النقاط، نقاط/ماتش، الفورمة، لعب كام ماتش، الأهداف والصناعات والكروت، نسبة اختياره، وجدول كل جولة (الخصم والنتيجة والنقاط). كله محسوب من إحصائيات الجولات الفعلية.

## تسجيل الدخول (Firebase Authentication)
**المشتركين:** أول ما حد يفتح الموقع من غير حساب بتظهر له شاشة **دخول / حساب جديد** (إيميل + باسورد + الاسم ورقم الموبايل). التشكيلة بتتحفظ باسم حسابه، وفيه زر "خروج" في الهيدر وزر "نسيت الباسورد".
**المنظم:** من الرابط **`/admin`** بنفس طريقة الدخول، بس لازم إيميله يكون في `ADMIN_EMAILS`.

الإعداد:
1. في [Firebase Console](https://console.firebase.google.com) اعمل مشروع، وفعّل **Authentication → Sign-in method → Email/Password**.
2. سيب **التسجيل الجديد (sign-up) مفعّل** عشان المشتركين يعملوا حسابات. صلاحية المنظم مش بتعتمد عليه، السيرفر بيقارن الإيميل بـ `ADMIN_EMAILS`.
3. اعمل حساب المنظم: سجّل حساب عادي بإيميلك من شاشة "حساب جديد"، أو من **Authentication → Users → Add user**.
4. من **Project settings → General** انسخ **Web API Key**. لو مقيّد المفتاح من Google Cloud، متحطش قيد "HTTP referrers" لأن السيرفر بيستخدمه كمان (قيّده بالـ API: Identity Toolkit).
5. في Vercel → **Settings → Environment Variables** ضيف:
   - `VITE_FIREBASE_API_KEY` = الـ Web API Key
   - `ADMIN_EMAILS` = إيميلات المنظمين مفصولة بفاصلة
6. اعمل **Redeploy** (المتغير `VITE_` بيدخل وقت البناء).

ملاحظات:
- لو `ADMIN_EMAILS` فاضي دخول المنظم مقفول بالكامل.
- لو `VITE_FIREBASE_API_KEY` مش مضبوط (تجربة محلية) مفيش شاشة دخول، والمنظم بيدخل بـ `ADMIN_KEY` والمشتركين بالتوكن القديم بتاع الجهاز.
- بعد تفعيل Firebase، التشكيلات القديمة اللي اتسجلت من غير حساب (باسم الجهاز) مش هتتربط بأي حساب جديد.

## التحويلات والكروت
- **تحويل مجاني واحد كل جولة** (الإعداد من لوحة المنظم ← الإعدادات). كل تحويل زيادة بيتخصم **4 نقاط** (قابل للتغيير). أول تشكيلة لأي مشترك من غير حدود.
- التحويلات بتتحسب على السيرفر بمقارنة التشكيلة بتشكيلة الجولة اللي قبلها، فمفيش تلاعب من الجهاز.
- **Wildcard**: تحويلات من غير خصم في جولة، مرة واحدة في الدورة. **Free Hit**: تحويلات حرة لجولة واحدة وبترجع التشكيلة القديمة بعدها، مرة واحدة.
- الخصم بيتحسب في نقاط الجولة في الترتيب والإحصائيات.

## الحساب التلقائي من المباريات
المباريات هي مصدر الحقيقة. كل ما تحفظ أو تسجّل مباراة السيرفر بيحسب تلقائي:
- **إحصائيات اللاعبين:** الأهداف والصناعات والكروت والهدف العكسي والجزاءات ورجل الماتش والكلين شيت والمشاركة (من أحداث المباراة المباشرة، أو من قائمة الهدافين المكتوبة بالأسماء).
- **نقاط الفانتازي** لكل مشترك وكل جولة (مع خصم التحويلات)، و**الترتيب العام**، و**جدول الفرق** (لعب/فوز/تعادل/خسارة/له/عليه/نقاط)، و**الهدافين**.
- الماتش اللي خلص ومحددتش فيه مين لعب: كل لاعبين الفريقين بيتحسبوا مشاركين (وبيتحسب كلين شيت للي ما اتدخلش عليه).
- علامة الهدف العكسي في القائمة المكتوبة لازم تبقى بين أقواس: `اسم اللاعب (ع.م)`.

## مسح البيانات التجريبية
- النسخة دي بتبدأ **فاضية**: من غير فرق ولا لاعبين ولا مباريات ولا إحصائيات ولا مشتركين تجريبيين.
- لو الموقع عندك فيه بيانات تجريبية متخزنة من قبل: لوحة المنظم ← **الإعدادات** ← **🗑 مسح كل البيانات التجريبية**. بيمسح الفرق واللاعبين والمباريات والإحصائيات وتشكيلات المشتركين، وبيرجّع الجولة 1. **الحسابات (الاسم والموبايل) بتفضل**.
- بعد المسح ضيف فرقك ولاعبينك ومبارياتك من اللوحة.

## ترتيب المشتركين
كل مشترك يقدر يشوف ترتيبه ونقاطه وسط باقي اللاعبين من مكانين: زر **🏆 ترتيب المشتركين** في شاشة فانتازي، وتبويب **المشتركين** في شاشة الترتيب والجدول. بيعرض المركز وحركة الصعود/النزول عن الجولة اللي فاتت ونقاط الجولة والمجموع، وبطاقة بترتيبك والفرق بينك وبين المتصدر. النقاط بتتحسب تلقائي من المباريات.

## لو لوحة المنظم مش بتفتح
افتح `/admin` وادخل بإيميلك. لو رفضك، الصفحة هتكتب السبب:
- **ADMIN_EMAILS مش مضبوط / الإيميل مش ضمنه:** ضيف إيميلك في Vercel بنفس الكتابة (مفيش فرق بين الحروف الكبيرة والصغيرة) وأعد النشر.
- **Firebase رفض التوكن:** تأكد من `VITE_FIREBASE_API_KEY`، ومن إن المفتاح في Google Cloud ← APIs & Services ← Credentials مش مقيّد بـ HTTP referrers (قيّده بالـ API بس). ممكن كمان تضيف `FIREBASE_REFERER` = رابط موقعك.
- بعد أي تعديل في المتغيرات اعمل **Redeploy**.

## قواعد Firebase (Rules)
الموقع بيستخدم Firebase للدخول (Authentication) بس، والبيانات على سيرفر Vercel. فعشان محدش يوصل لأي قاعدة بيانات في المشروع بالـ API Key العام، الملفات في مجلد `firebase/` بتقفل Realtime Database وFirestore وStorage بالكامل. انسخ محتوى كل ملف في تبويب Rules بتاع الخدمة في Firebase Console، أو انشرها بـ `firebase deploy --only database,firestore,storage` من داخل مجلد `firebase/`. تسجيل الدخول مش محتاج Rules.

## التخزين على Firebase Firestore
بيانات الدورة (الفرق واللاعبين والمباريات والإحصائيات والتشكيلات) بتتخزن في **Firestore** لما تضيف `FIREBASE_SERVICE_ACCOUNT`.
التطبيق مش بيكلم Firestore من المتصفح: السيرفر بس هو اللي بيقرأ ويكتب بحساب خدمة، فالتحقق من الميزانية والتحويلات والنقاط بيفضل على السيرفر. عشان كده **قواعد Firestore لازم تفضل مقفولة بالكامل** (`allow read, write: if false`) والسيرفر بيتخطاها لأنه بيدخل بصلاحيات حساب الخدمة.

الإعداد:
1. Firebase Console ← **Build ← Firestore Database ← Create database** (اختار Production mode وأقرب منطقة).
2. **Rules** في Firestore: سيبها `allow read, write: if false;` واضغط Publish.
3. **Project settings ← Service accounts ← Generate new private key**: هينزل ملف JSON.
4. Vercel ← Settings ← Environment Variables: ضيف `FIREBASE_SERVICE_ACCOUNT` وحط فيه **محتوى ملف الـ JSON كله**. (ده سر: متحطوش في GitHub ولا في الكود.)
5. **Redeploy**.

- لو كان عندك Upstash Redis قبل كده وسيبته متوصل، أول طلب بينقل بياناتك القديمة لـ Firestore تلقائيًا مرة واحدة (لو Firestore فاضي).
- المستندات: `tournament/main` (الدورة)، `entries/{uid}` (تشكيلة كل مشترك).
- الحصة المجانية لـ Firestore (خطة Spark): 50 ألف قراءة و20 ألف كتابة في اليوم. السيرفر بيستخدم كاش قصير والشاشات بتتحدث كل 10 ثواني عشان القراءات تفضل قليلة، لكن لو عندك مئات المشتركين الأفضل تفعّل خطة Blaze.
